SOP and POS: Two Canonical Forms

Every truth table can be read two ways. Read the 1-rows: each one is a minterm, a product (AND) of every literal that’s true for that row. OR all the minterms together and you get the sum-of-products (SOP) form — the canonical form used throughout the K-map lesson.

Read the 0-rows instead: each one is a maxterm, a sum (OR) of literals — but with the polarity flipped, so a variable that’s 1 in that row appears complemented, and a variable that’s 0 appears plain. AND all the maxterms together and you get the product-of-sums (POS) form.

Key idea: SOP and POS describe the exact same function from opposite directions. SOP says “output is 1 when any of these conditions hold.” POS says “output is 1 unless one of these conditions fails.” Both are always available — which one minimizes smaller depends on the function.

Minimizing SOP with K-Maps

Group the 1s using the grouping rules from the previous lesson: powers of 2, as large as possible, every 1 covered, minimum number of groups. Each group becomes one product term; OR the terms together.

Example 1. F(A,B,C) = Σ(0, 1, 2, 3, 5, 7)
A \ BC00011110
0 1m0 1m1 1m3 1m2
1 0m4 1m5 1m7 0m6
  • Top row: A = 0 constant → A′
  • Middle two columns: C = 1 constant → C

Minimal SOP: F = A′ + C

Example 2. F(A,B,C,D) = Σ(0, 4, 8, 12, 13, 14, 15)
AB \ CD00011110
00 1m0 0m1 0m3 0m2
01 1m4 0m5 0m7 0m6
11 1m12 1m13 1m15 1m14
10 1m8 0m9 0m11 0m10
  • CD = 00 column, all rows (wraps top-to-bottom): C′D′
  • AB = 11 row: AB

Minimal SOP: F = C′D′ + AB

Minimizing POS with K-Maps

Same map, same rules — but this time group the 0s. Each group of 0s becomes one sum term, with the polarity of every constant literal flipped from the SOP convention (constant 1 → complemented, constant 0 → plain). AND the sum terms together.

Example 3. F(A,B,C) = Σ(0, 1, 2, 3, 5, 7) — same function as Example 1
A \ BC00011110
0 1m0 1m1 1m3 1m2
1 0m4 1m5 1m7 0m6
  • m4 and m6, the two outer columns of row A = 1 (wraps left-right): A = 1 → A′, C = 0 → C, B varies and drops

Minimal POS: F = (A′ + C)

Here the minimal POS collapses to the same single term as the minimal SOP — a reminder that SOP and POS aren’t two different answers, just two different routes to whatever the smallest expression happens to be.

Example 4. F(A,B,C) = Σ(1, 3, 4, 6, 7)
A \ BC00011110
0 0m0 1m1 1m3 0m2
1 1m4 0m5 1m7 1m6
  • m0 and m2, row A = 0 (columns 00 and 10): A = 0 → A, C = 0 → C → (A + C)
  • m5 alone, no adjacent 0 to pair with: A = 1 → A′, B = 0 → B, C = 1 → C′ → (A′ + B + C′)

Minimal POS: F = (A + C)(A′ + B + C′)

An isolated 0 with no legal neighbor still forms a valid group of size 1 — it just costs a full-width sum term instead of a short one. Always check both SOP and POS on a function like this; whichever needs fewer terms and literals is the cheaper circuit.

NAND-Only Implementations

Every two-level AND-OR circuit converts directly into a two-level NAND-NAND circuit with the identical wiring — only the gates change. The proof is a double negation plus De Morgan’s law:

P₁ + P₂ + … + Pₙ = (P₁′ · P₂′ · … · Pₙ′)′ = NAND(NAND(P₁), NAND(P₂), …, NAND(Pₙ))

  1. Replace every first-level AND gate with a NAND gate. Each one still takes the same literals as inputs.
  2. Replace the final OR gate with a NAND gate too. Its inputs are the outputs of the first-level NANDs.
  3. Give any bare single-literal term its own inverter. In the AND-OR version a lone literal is just a wire with no gate on it; to fit the NAND pattern it needs an actual inversion, made by tying both inputs of a 2-input NAND together — NAND(X, X) = (X·X)′ = X′.
Example 5. F = AB + CD, as NAND-NAND

F = NAND( NAND(A, B), NAND(C, D) )

Example 6. F = A + BC, as NAND-only (needs an inverter)

The top gate is a 2-input NAND with both inputs tied to A — an inverter, producing A′. The bottom gate is an ordinary 2-input NAND on B and C, producing (BC)′. The final NAND recombines them: F = NAND(A′, (BC)′) = (A′)′ + ((BC)′)′ = A + BC.

F = NAND( NAND(A, A), NAND(B, C) )

NOR-Only Implementations

POS has the exact dual conversion. A two-level OR-AND circuit (sum terms feeding a final AND) becomes a two-level NOR-NOR circuit, gate for gate:

S₁ · S₂ · … · Sₙ = (S₁′ + S₂′ + … + Sₙ′)′ = NOR(NOR(S₁), NOR(S₂), …, NOR(Sₙ))

  1. Replace every first-level OR gate with a NOR gate. Same literals in, complemented sum out.
  2. Replace the final AND gate with a NOR gate too. Its inputs are the first-level NOR outputs.
  3. Give any bare single-literal factor its own inverter — a 2-input NOR with both inputs tied together: NOR(X, X) = (X+X)′ = X′.
Example 7. F = (A + B)(C + D), as NOR-NOR

F = NOR( NOR(A, B), NOR(C, D) )

Example 8. F = A(B + C), as NOR-only (needs an inverter)

The top gate is a 2-input NOR with both inputs tied to A, giving A′. The bottom gate is an ordinary 2-input NOR on B and C, giving (B+C)′. The final NOR recombines them: F = NOR(A′, (B+C)′) = (A′)′ · ((B+C)′)′ = A(B+C).

F = NOR( NOR(A, A), NOR(B, C) )

Common mistake: mixing NAND-NAND with NOR-NOR bubble math. The two conversions are duals of each other — don’t try to build an SOP expression out of NOR gates (or a POS expression out of NAND gates) by simply swapping gate names; re-derive the levels from the appropriate identity instead.
