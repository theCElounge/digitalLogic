Simulation & Testbenches

Verify your circuit in software before it ever touches the board: write a testbench, run the Vivado simulator, and read waveforms like a pro.

Why simulate first

Programming the board takes minutes; a simulation runs in seconds and shows you every internal signal, not just the LEDs. From Lab 4 onward the rule is: never program a design you haven't simulated. A testbench is a Verilog module with no ports that (1) instantiates your design — the DUT, device under test — (2) wiggles its inputs, and (3) checks or displays the outputs.

A complete testbench

full_adder_tb.v — exhaustive test of the Tutorial 2 full adder
`timescale 1ns / 1ps      // time unit / precision for delays

module full_adder_tb;      // no ports!

    // 1. Signals: reg for DUT inputs (we drive them), wire for outputs
    reg  a, b, cin;
    wire s, cout;

    // 2. Instantiate the device under test
    full_adder dut (.a(a), .b(b), .cin(cin), .s(s), .cout(cout));

    // 3. Drive every input combination
    integer i;
    initial begin
        for (i = 0; i < 8; i = i + 1) begin
            {a, b, cin} = i[2:0];   // unpack loop counter onto inputs
            #10;                     // wait 10 ns for outputs to settle
            $display("a=%b b=%b cin=%b  ->  cout,s = %b%b",
                      a, b, cin, cout, s);
        end
        $finish;                     // end the simulation
    end
endmodule
  • initial blocks run once, starting at time 0 — they exist only for simulation; you can't synthesize them onto the board.
  • #10 means "wait 10 time units" (nanoseconds here, set by `timescale).
  • $display prints to the simulator console; %b formats in binary. $monitor is similar but prints automatically whenever a listed signal changes.
  • An 8-row loop fully tests a 3-input circuit. Exhaustive testing is feasible up to ~10 inputs; beyond that you test representative and corner cases.

Running it in Vivado

  1. Add the testbench as a simulation source: Sources → + → Add or create simulation sources. It appears under Simulation Sources, not Design Sources — testbenches never go to the board.
  2. Check that the testbench is bold (set as top). If not: right-click → Set as Top.
  3. Flow Navigator → Run Simulation → Run Behavioral Simulation.
  4. The waveform window opens. Click Zoom Fit (or press Ctrl+F …the magnifier icon) to see the whole run. Your $display output is in the Tcl Console below.
  5. To watch internal signals (like the carries inside the adder): expand dut in the Scope panel, drag signals into the wave window, then restart the run (Run → Restart, then Run All).
If simulation "hangs": a testbench with a forever clock (Tutorial 5) never stops on its own. Use Run For 1000 ns instead of Run All, or make sure your stimulus ends with $finish.

Reading a waveform

Three habits that make waveform debugging fast:

  • Verify against the truth table. At each 10 ns step, read inputs → predicted output → actual output. For the full adder, at a=1, b=1, cin=1 you must see cout=1, s=1.
  • Group buses and set the radix. Right-click a multi-bit signal → Radix → Unsigned Decimal (or Hexadecimal) to read values like a human.
  • Red means trouble. A red X is an unknown/uninitialized value; a Z is a floating (unconnected) wire — usually a port you forgot to hook up in the instantiation.
