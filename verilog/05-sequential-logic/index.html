Sequential Verilog: Clocks, Registers & Counters

Circuits with memory: flip-flops in Verilog, the blocking vs. non-blocking rule, resets, and taming the Basys 3's 100 MHz clock so humans can watch a counter count.

The edge-triggered always block

One change of sensitivity list turns Verilog combinational logic into a flip-flop: react to a clock edge instead of to input changes.

dff.v — D flip-flop with asynchronous reset
module dff(
    input  wire clk, rst, d,
    output reg  q
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            q <= 1'b0;    // reset wins, immediately
        else
            q <= d;       // otherwise capture d at the clock edge
    end
endmodule
  • always @(posedge clk) = "do this at each rising clock edge." Now reg q really does become a hardware register.
  • Including or posedge rst makes the reset asynchronous (acts instantly). Omit it and check rst inside for a synchronous reset (acts at the next edge). Either is fine in this course — be consistent.
  • Note the new operator: <=. That's next.

Blocking vs. non-blocking — the rule that saves your semester

Verilog has two assignment operators, and mixing them up is the classic sequential-logic bug:

OperatorNameBehaviorUse in
=BlockingExecutes immediately, in order — like softwareCombinational always @(*)
<=Non-blockingAll right-hand sides read first, all updates land together at the edge — like real flip-flopsClocked always @(posedge clk)
Why it matters: a 2-stage shift register
// CORRECT (non-blocking): q1 and q2 update simultaneously.
// q2 gets the OLD q1 -> a true 2-flip-flop shift register.
always @(posedge clk) begin
    q1 <= d;
    q2 <= q1;
end

// WRONG (blocking): q1 updates first, THEN q2 reads the NEW q1.
// Both lines collapse into ONE flip-flop: q2 == q1 == d.
always @(posedge clk) begin
    q1 = d;
    q2 = q1;
end
Memorize the rule: <= in clocked blocks, = in combinational blocks, never mix them in one block, and never assign the same signal from two different always blocks.

Slowing down 100 MHz

The Basys 3 clock ticks 100 million times per second — a counter on LEDs would be an invisible blur. The standard trick: run a wide free-running counter and use its top bit, which toggles a human-speed square wave.

clk_div.v — from 100 MHz to ~0.75 Hz
module clk_div(
    input  wire clk,          // 100 MHz board clock (pin W5)
    input  wire rst,
    output wire slow          // count[26] toggles ~0.75 times/sec
);
    reg [26:0] count;
    always @(posedge clk or posedge rst) begin
        if (rst) count <= 27'd0;
        else     count <= count + 1;
    end
    assign slow = count[26];  // 100 MHz / 2^27  ≈ 0.75 Hz
endmodule
  • Good practice: use slow as a 1-bit enable for logic still clocked by clk, rather than as a new clock, once designs grow. For this course's LED-speed labs, either works — we discuss why in week 13.

Putting it together: a visible counter

top.v — Lab 9 core: 4-bit counter on LEDs
module top(
    input  wire       clk,     // 100 MHz
    input  wire       btnC,    // center button = reset
    output wire [3:0] led
);
    wire slow;
    clk_div div0 (.clk(clk), .rst(btnC), .slow(slow));

    reg [3:0] count;
    always @(posedge slow or posedge btnC) begin
        if (btnC) count <= 4'd0;
        else      count <= count + 1;
    end

    assign led = count;
endmodule

Uncomment clk (pin W5), btnC (U18), and the four led pins in the XDC. Program it and watch binary counting at last — this is the moment the whole foundations unit becomes physical.

Buttons bounce. A mechanical press produces dozens of electrical edges over a few milliseconds. Use buttons for resets (harmless), but to count presses you need the debouncer from Lab 8 — otherwise one press adds a random number.
