Behavioral Modeling: always, if & case

Describe what a circuit does instead of which gates it uses — multiplexers, decoders, and the seven-segment display, plus the accidental-latch trap every beginner hits.

From structure to behavior

Dataflow modeling is fine for small equations, but describing a 7-segment decoder with sixteen assign terms is miserable. Behavioral modeling lets you write the truth table almost directly, and the synthesizer picks the gates.

The behavioral pattern
reg y;                    // targets of always blocks are declared reg
always @(*) begin         // @(*): re-evaluate when ANY input changes
    // if / case statements describing the behavior
end
  • always @(*) defines a block of behavior for combinational logic. The * auto-builds the sensitivity list — always use it; hand-written lists cause simulation/hardware mismatches.
  • A signal assigned inside an always block must be declared reg. Despite the name, reg does not mean a register is created — it's just a Verilog rule about where assignments may appear.

Multiplexer, three ways

mux4.v — a 4-to-1 multiplexer
module mux4(
    input  wire [3:0] d,      // four data inputs d[3..0]
    input  wire [1:0] sel,    // select lines
    output reg        y
);
    always @(*) begin
        case (sel)
            2'b00:   y = d[0];
            2'b01:   y = d[1];
            2'b10:   y = d[2];
            2'b11:   y = d[3];
            default: y = 1'b0;   // safety net
        endcase
    end
endmodule

// The same mux in one dataflow line (conditional operator):
//   assign y = d[sel];
//   assign y = sel[1] ? (sel[0] ? d[3] : d[2])
//                     : (sel[0] ? d[1] : d[0]);

The accidental latch — the #1 beginner bug

In combinational always blocks, every output must be assigned on every possible path. If some input combination assigns nothing, the synthesizer must remember the old value — so it silently infers a latch. Your "combinational" circuit now has memory, and behaves unpredictably in hardware.

BROKEN — infers a latch
always @(*) begin
    if (en)
        y = a & b;
    // no else!  When en == 0, y keeps its old value -> LATCH
end
FIXED — every path assigns y
always @(*) begin
    if (en)
        y = a & b;
    else
        y = 1'b0;
end

// Equally good: a default value up front
always @(*) begin
    y = 1'b0;          // default first
    if (en) y = a & b; // override when needed
end
Spot it in the tools: Vivado's synthesis log warns inferring latch for variable 'y'. In this course, that warning in a combinational design is always a bug. The fixes: add else, add default: to every case, or assign defaults at the top of the block.

Worked example: hex to seven-segment decoder

The Basys 3's four-digit display is active-low: a segment lights when its signal is 0. The pattern {g,f,e,d,c,b,a} below drives one digit; an enables digits (also active-low).

sseg_decoder.v — used in Lab 7 and the project
module sseg_decoder(
    input  wire [3:0] hex,     // value 0-F
    output reg  [6:0] seg      // {g,f,e,d,c,b,a}, ACTIVE LOW
);
    always @(*) begin
        case (hex)
            4'h0: seg = 7'b1000000;
            4'h1: seg = 7'b1111001;
            4'h2: seg = 7'b0100100;
            4'h3: seg = 7'b0110000;
            4'h4: seg = 7'b0011001;
            4'h5: seg = 7'b0010010;
            4'h6: seg = 7'b0000010;
            4'h7: seg = 7'b1111000;
            4'h8: seg = 7'b0000000;
            4'h9: seg = 7'b0010000;
            4'hA: seg = 7'b0001000;
            4'hB: seg = 7'b0000011;
            4'hC: seg = 7'b1000110;
            4'hD: seg = 7'b0100001;
            4'hE: seg = 7'b0000110;
            4'hF: seg = 7'b0001110;
            default: seg = 7'b1111111;   // all off
        endcase
    end
endmodule

Notice the shape: this is a truth table — sixteen rows, one output pattern per row. That's the power of behavioral modeling.
